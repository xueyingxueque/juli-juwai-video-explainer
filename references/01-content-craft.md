## 1. 成功标准与失败信号

成片不是「把剧情讲清楚」就完事。同时满足才算成功：

| # | 标准 |
|---|---|
| 1 | 剧情准确：人物关系、关键事件、时序推进无误 |
| 2 | 戏眼命中：最有表演张力的原台词被优先保留，而不是只选「能说明剧情」的 |
| 3 | 解说克制：只做铺垫 / 跳转 / 补信息，不复述原片已说清的内容 |
| 4 | 情绪完整：保留羞辱 → 反抗 → 落难 → 安慰 → 反转 → 站队这类链条 |
| 5 | 结构可执行：`spec` 直接用于采证据、配音、裁切 |
| 6 | 节奏达标：开头快、原片不过量、长原片不过多、结尾干净 |

**失败信号（命中即返工）**：空泛包装词（命运 / 站稳 / 移不开眼 / 齿轮开始转动）；
选了「能讲明白」却漏掉「最有戏」的片段；只留结果不留过程；
`original` 段写成摘要标签而不是真实台词；VO 紧挨着复述原片；
结尾同时想做原片落刀和 VO 挂钩。

## 2. 六段式骨架与情绪链条

`config/engine.json → content_policy.structure` 定义默认骨架：
开场钩子 → 快速补前情 → 第一次正面碰撞 → 连续升级 → 反转/反击/情绪爆点 → 结尾落点。

- **必须交给原片**：一句话立住人物、羞辱感最强、反击快感最强、情绪落点、表演强于信息。
- **必须交给解说**：跨场景推进、重复争吵、背景说明、爆点之间的桥段、为节奏必须带过的说明。
- **镜头序按剧本 block 曲线重排**，严禁按集数顺序灌（F8）；同集连续上限见 `content_policy.max_same_ep_run`。

## 3. 节奏预算

写 spec 前先答出这六项，答不出不许进最终分镜：

| 字段 | 来源 | 说明 |
|---|---|---|
| `target_sec_range` | `duration_policy.bounds` | 实测严格 60–300s |
| `vo_ratio` / `raw_ratio` | 段数计算 | 建议解说 60–75% / 原片 25–40%（按题材微调） |
| `hook_first_cut_sec` | cold_open | 有冷开场即 **0s** 出刀；无冷开场须 ≤8s |
| `long_original_count` | 段时长 | 长原片 >15s 须逐段写理由，数量 ≤2 |
| `ending_strategy` | 末段模式 | 原片最后一刀 / VO 挂钩，**二选一** |

> 实测教训：`content_brief.py` 第一版把 cold_open 排除后再找「第一个冲突块」，
> 把已经 0 秒出刀的 MW1 误判成 21.93s。判据必须回答真正的问题，不是照字面套模板。

## 4. Kill List 与插片理由

`brief-<ep>.json` 的 `kill_list` 由本地可算信号生成：同集连续超限、
原声占比超上限、超长原片过多、空泛词命中、开头第一刀超时。

`segment_reasons` 给**每一段**写一句理由（前 3 秒钩子 / 保留台词张力 /
解说承担铺垫跳转补信息），让选片决策可审计，而不是藏在人脑里。

## 5. content_brief.py 怎么落地

```bash
python scripts/content_brief.py <任务目录> <ep>          # 生成 _plan/brief-<ep>.json
python scripts/content_brief.py <任务目录> <ep> --strict  # REWORK 时退出码 1
```

默认**只报告不拦**（已交付集不该被新判据否定）；`--strict` 才作为闸门。
`quality_checklist` 分 `auto`（脚本判定）与 `manual`（需抽帧/回听）两类，
进度不可把 manual 项伪装成通过。

2026-11-09 对 6 支已交付成片全量跑过：均 `PASS`，第一刀 0.0s、长原片 0。

## 6. 边界：脚本不评审美

镜头重要性、表演张力、观众是否记得住某一句——这些**没有客观判据**，
脚本不假装能评。本层只把「可计算、可核对、可返工」的部分固化，
主观判断仍交给 Agent 结合 transcript 与抽帧。对标仓库同样把
`dramatic editor` 设为专门子任务而非自动评分器。
