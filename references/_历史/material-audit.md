# 素材性质审核：素材库是「解说成片」，不是原片

> 用户提问：「先不要用 一池好宴 做演示素材, 这个第一集本来就是解说,
> 你能分清哪些字幕是解说, 哪些是原片吗」
> 审核日期：2026-08-08

---

## 结论

**素材库 339 条视频全部是「解说成片」（他人已剪好的解说视频），不是原始短剧素材。**

**回答用户的问题：分不清。因为整个音轨/字幕就是解说，没有"原片字幕"可言。**

---

## 三项实测证据（以 一池好宴/1.mp4 为例）

### 证据 1：画面规格 = 解说成片特征

| 项 | 实测值 | 原片应该是 |
|---|---|---|
| 分辨率 | **1080×1920（9:16 竖屏）** | 1920×1080 横屏 或 原始竖屏剧集 |
| 时长 | 147.2s | 一集短剧通常 5-15 分钟 |
| 字幕 | 画面底部**硬字幕**（白色+描边） | 原片一般无字幕或用平台字幕 |
| 内嵌字幕流 | **无**（`select_streams s` 为空） | — |

### 证据 2：画面里有解说模板元素

抽帧目视检查：

**一池好宴/1.mp4**（20 秒处）
- 底部白色描边字幕「竞争餐饮集团合伙人」
- 画面是摆盘精致的菜肴特写 —— **这是解说剪辑后的镜头**

**快手/山藏万象/剧集/1.mp4**（20 秒处）
- 柴犬戴着护目镜，脖子挂**人物标签牌「高冷」**
- 底部小字幕「啊」
- **人物标签是解说视频的典型手法**

**视频号/念念有深 首发21集/01.mp4**（20 秒处）
- 底部字幕「那天报了火警的人」
- 画面经过调色（高对比、暖色调）—— **解说片的调色风格**

### 证据 3：音频是 TTS 旁白，不是原片音轨

```
采样率 16000  时长 147.2s
静音帧占比(<-40dB): 0%          ← 几乎无静音
平均响度 -15.3 dB  峰值 -3.9 dB
动态范围 P95-P10 = 18.4 dB     ← 动态很小
```

**判据**：
- 原片音轨（对白+环境音）动态范围通常 **>25 dB**，有明显的环境音起伏
- **TTS 旁白**经过压缩处理，动态范围 **<20 dB**，且几乎无静音（旁白是连续的）

实测 18.4 dB + 0% 静音 → **典型 TTS 解说旁白音轨**。

---

## 这对引擎意味着什么（影响面很大）

### ★ 之前所有的 S1/S2/S3 验证都建立在错误前提上

| 环节 | 原以为 | 实际 |
|---|---|---|
| 画面字幕 | 原片对白（可作事实锚点） | **他人解说的旁白文本** |
| 音频 | 原片音轨 | **他人解说的 TTS 旁白** |
| 「原声」 | 可从素材提取原片对白 | **根本没有原声**，只有他人旁白 |

**所以之前那些"锚点门""主体错配""性别搞反"等发现，可能有一部分是被解说字幕误导的假象。**

### 具体影响

1. **画面字幕锚点门**：锚的其实是"别人的解说文本"，不是原片事实
2. **对白时间戳清单**（`dialogue.json` 108 段）：是他人旁白的时间轴，**不能当原声用**
3. **原声设计**：前提不成立 —— **没有原片音频可提取**
4. **S4 成片**：无法"保留角色原声"，因为素材里没有角色原声

---

## 引擎能做什么 / 不能做什么（用这类素材）

### ✅ 能做
- **二次创作**：把别人的解说稿当参考，改写成自己的解说
- **风格学习**：分析爆款的钩子、节奏、段落结构（这正是我这几轮在做的）
- **素材复用**：剪出片段重新编排

### ❌ 不能做
- **提取原片对白**：素材里没有
- **保留角色原声**：同上
- **"还原真实剧情"**：字幕是他人加工过的，不是原片事实
- **原声/画面重排**：没有真正的原片素材

---

## 真正需要什么素材

要让引擎按设计工作（尤其原声功能），需要的是**原始短剧素材**：

| 需求 | 素材规格 |
|---|---|
| 竖屏短剧剧集 | 1080×1920 或 720×1280，**无解说字幕**，5-15 分钟/集 |
| 或横屏原片 | 1920×1080，完整对白 |
| 关键 | **画面不能有解说模板元素**（人物标签、旁白字幕、调色风格） |
| 关键 | **音轨是原片对白+环境音**，不是 TTS 旁白 |

### 素材来源建议
1. 短剧平台的**官方剧集页**原始资源
2. 版权方授权的完整剧集
3. 自己拍摄/录屏的原片

**在拿到真正的原片素材前，引擎的 S4（原声/成片）无法验证。**

## 检测脚本（可复用）

新建建议：`scripts/material_probe.py`，对每条素材输出：
```json
{
  "path": "...",
  "resolution": "1080x1920",
  "duration": 147.2,
  "has_burned_subtitle": true,
  "has_person_label": false,
  "audio_dynamic_range_db": 18.4,
  "silence_ratio": 0.0,
  "verdict": "解说成片" | "疑似原片",
  "confidence": "high"
}
```

判据组合（三条都命中才算解说成片）：
1. 有硬字幕
2. 动态范围 < 20dB 且静音 < 5%
3. 画面有解说模板元素（人物标签/调色）

## 九、v2.7 源头级修复（不只是写报告）

### 9.1 素材预检门 `scripts/material_precheck.py` —— 已在源头拦住

**审计发现**：用户提问前，引擎对素材性质**毫无察觉**，
所有下游门（锚点门/主体门/POV门）的判据都建立在「这是原片」这个错误前提上。
**根因不是某个门失灵，是没有门去问"这到底是什么素材"。**

**三条独立信号，两条命中即判「解说成片」**：

| 信号 | 判据 | 实测（一池好宴/1.mp4） |
|---|---|---|
| `audio_like_tts` | 动态范围 <20dB 且静音 <5% | ✔ 18.4dB / 0% |
| `too_short` | 时长 <240s | ✔ 147.19s |
| `frame_template` | VLM 检出人物标签牌/花字 | （需 evidence） |

**实测拦截结果**（`pipeline.py run` 端到端）：
```json
{"status": "failed", "code": "MATERIAL_IS_NARRATED_VIDEO",
 "signals": [{"name":"audio_like_tts","hit":true,"detail":"动态范围 18.4dB(<20) 且静音占比 0%"},
             {"name":"too_short","hit":true,"detail":"时长 147.19s < 240s"}],
 "usable_as": "爆款参考库（只能学写法，不能提取原片事实/原声）"}
```

**已接入 `pipeline.py run` 首位**：不合格直接 `MATERIAL_IS_NARRATED_VIDEO` 返回码 2，
不再进入 S1-S3 浪费一轮。

### 9.2 `frames_desc` 改为结构化输出 —— 从根上区分「画面的人」与「说话的人」

这是**上一轮审核挖出的根本问题**，现在在源头修掉。

**旧输出**（混在一起，下游无法区分）：
```json
{"evidence_id":"E015","desc":"一位女性，捂眼含泪…字幕：我要退学去打工"}
```

**新输出**（三字段分离）：
```json
{"evidence_id":"E015",
 "frame_who":"年轻女性，捂右眼，含泪",
 "subtitle_text":"我要退学去打工",
 "speaker":"无法判断",        // 画面内男性/女性/画外音/内心独白
 "desc":"她正在哭泣说话"}
```

**提示词明确要求**：
> ★ 若字幕是画外音或他人对白，出镜者不是说话人，`speaker` 不要填「画面内…」。

**连带修复**：`extract_onscreen_text()` 改用 `subtitle_text` 字段抽取锚点
（回退到 `desc` 引号内容），使锚点来源更可靠。

### 9.3 为什么这两处才算「源头」

| 处置 | 性质 | 效果 |
|---|---|---|
| 写一份审核报告 | **补丁**（给人看） | 引擎下次跑照样不知道素材是啥 |
| 加一道质检门 | **补丁**（事后拦） | 会先跑完 S1-S3 才被拦，浪费 |
| **素材预检门接进 run 首位** | **源头** | 不合格根本不进生产 |
| **frames_desc 结构化输出** | **源头** | 下游判据的正确前提被打进数据 |
