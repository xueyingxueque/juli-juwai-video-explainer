### 第 1 步已完成（试跑验证质量）

`series_decompose.py` 每集做三件事：

**结构化读帧输出**（v2.7 修复后的格式）：

`speaker` 正确区分「画面内女性 / 画外音 / 内心独白」——**这正是我之前栽过的坑，现在在源头修好了**。

### ★ 张力打分的坑（试跑发现并修复）

**初版只看字幕关键词**（决战/秒杀/碾压），结果 **16 个事件全部判 L0**。

**根因**：这是「乡村萌宠 + 修仙」题材，最强画面是「黑熊张开大嘴咆哮」，
**根本没有那种关键词**。

**修法**：张力改为**画面 + 台词双维**，画面权重更高：

| 维度 | 词表示例 | 权重 |
|---|---|---|
| 画面冲击 | 扑/撕/撞/砸/砍/刺/张口/大嘴/锋利/咆哮/光芒/剑气/爆炸/变身 | 0.26/个，上限 0.62 |
| 画面对抗 | 对峙/怒视/争执/阻拦/推/追/闪/警惕 | 0.10/个，上限 0.30 |
| 画面铺垫 | 田/屋/院子/村/走路/背影/远望 | 0.05/个，上限 0.10 |
| 台词高潮 | 决战/反杀/打脸/逆袭/真相/身份/竟 | 0.12/个，上限 0.24 |
| 台词对抗 | 骂/怒/嘲讽/威胁/抢/背叛/算计/羞辱 | 0.07/个，上限 0.14 |

**分档**：画面冲击 ≥2 → L3高潮；有画面冲击或台词高潮 → L2；
有对抗或铺垫 → L1；否则 L0。

**修复效果验证**：
| 事件 | 修复前 | 修复后 |
|---|---|---|
| 黑熊张开嘴咆哮 | **L0 / 0.00** | **L2 / 0.26（跃居第一）** |
| 抢东西还说这么大声 | L2 / 0.12 | L1 / 0.07 |

**教训**：关键词打分对**题材是有偏的**。乡村萌宠剧的高潮是「黑熊扑来」，
不是「决战」。**必须让画面参与打分，不能只靠台词。**

## 六、流水线续跑与进度（2026-08-11 续）

### 断点续跑机制

`series_decompose.py` 每集完成即写 `episodes/E{NNN}.json`，重跑时已存在的直接跳过。
实测验证：10 集已完成后重跑，从第 11 集继续，未重复劳动。

### ★ 工程坑：后台跑长任务不要用 `| head -N`

第一次续跑用 `| head -4`，管道提前关闭导致进程被掐，**跑了 2 分钟只完成 0 集**。
正确做法：**日志重定向到文件**，不截断：

```bash
python series_decompose.py <src> <out> > <out>/decompose.log 2>&1
```

### 去重逻辑（实测生效）

源目录 176 个文件 = 88 集 × 2（`1.mp4` 与 `第88集.mp4` 两套命名，内容相同）。
`pick_unique()` 按集号去重并选文件更大的那份，**丢弃 88 个重复副本**。

日志首行：
```
扫描 176 个文件，去重后 88 集（丢弃 88 个重复副本）
```

### 单集耗时与总时长

| 项 | 实测 |

| 88 集合计 | 约 100 分钟 |

### 新增 `scripts/series_plan.py`（故事线重排）

这是「不按视频顺序、重新梳理故事线、高潮前置」的实现：

**1. `pick_beats()` 挑主线高潮**
- 只取 L2 以上事件
- **同一集最多取 1 个**（保原创度，不整集照搬）
- **相邻集（±1）跳过**（保证跨集取样，节奏不塌）

**2. `infer_arc()` 推断故事弧**
按集号在总集中的相对位置划阶段（起/承/转/合），
**但输出顺序按张力排** —— 既保留剧情逻辑（能看出是同一条线），
又实现「不按视频顺序」的要求。

**3. `build_series()` 拆系列 + 高潮前置**
每条叙事顺序 = **[该条最高潮] → [铺垫] → [展开] → [收束]**
**开场直接放最炸的那一刻** —— 这正是真实爆款的倒叙钩子做法。

产出 `series-plan.json`：系列结构 + 每条的混剪清单（含 ep/t/台词/张力）。

## 七、★ 张力判定：从词表打分升级为语义判定（2026-08-11）

### 问题：词表打分严重漏判

用 18 集（142 事件）实测两种打分方式：

| 方式 | 高潮 | 冲突 | 铺垫 | 平静 |
|---|---|---|---|---|
| **词表打分** | 1 | 4 | 27 | **110（77%）** |
| **语义判定（VLM）** | 35 | 36 | 70 | **9（6%）** |

**具体漏判案例**：
- 「小女孩**双手握着一把大刀**，表情严肃地盯着前方」→ 词表判 **L0**，语义判 **L3/0.70**
- 「狗仰头嚎叫，背景中有**发光的狼形轮廓**」→ 词表判 L0，语义判 L3/0.70
- 「小女孩双手握棍，**仰头怒吼**，表情愤怒」→ 词表判 L0，语义判 L3/0.70

**根因**：关键词打分**对题材有偏**。我写的词表是按「都市逆袭」题材设计的
（决战/秒杀/碾压），遇到「乡村萌宠+修仙」就全部失效。

### 修法：`tension_llm()` —— 问模型而不查词表

判据从「有没有关键词」改成「**这个镜头对观众造成的情绪冲击**」：

```
0.0-0.3 平静：日常、闲聊、静态画面
0.3-0.5 有点紧张：对峙、怀疑、警惕
0.5-0.7 明显冲突：追逐、对抗、威胁、工具对峙
0.7-1.0 高潮爆发：攻击、受伤、变身、真相揭示、死亡、震惊、异象
```

提示词里特别注明：
> 这可能是乡村萌宠/修仙题材，**「小动物」「小孩」「异常发光」本身也可以是高张力**，
> 不要因为「画面看起来平静」就一律给低分。

**词表降级为回退**（VLM 不可用时才用）。

## 八、★ 修「数数误判」并在源头固化（2026-10-11 16:57-17:20）

### 误判根因（不是模型傻，是我的提示词有洞）

模型把「小女孩举起三根手指说『六』」判 0.70，给的理由是：

> 「数字与手势**不符制造认知冲突**，破旧书暗示异常」

**它在纠结"六"和三根手指对不上。** 但真相是：
字幕说「六」可能是「六根胡萝卜」，画面只举了三根 —— **这是抽帧与字幕不同步的假象，不是剧情异常**。

**这与之前踩的「字幕主体≠画面主体」是同一类问题的另一个面**：
字幕是对白的一瞬，画面也是一瞬，**两者时间不一定对齐，不能拿不一致当线索**。

### 提示词迭代了三版

| 版本 | 改动 | 数数 | 屠万鬼谷 | 问题 |
|---|---|---|---|---|
| v1 初版 | 问「情绪冲击」 | **0.70** ✗ | 0.90 | 数数被当异常 |
| v2 修误判 | 加「单帧信息不足保守给低分」 | 0.30 ✓ | **0.60** ✗ | 保守过头，压低真高潮 |
| **v3 平衡** | 「只往下调，不往上加」+「明确事件不压低」 | **0.30** ✓ | **0.90** ✓ | — |

**最终提示词三条硬规则**：

1. **字幕与画面不一定同步，不一致≠异常**
   （字幕是对白可能说到一半，两者对不上是正常的）
2. **只往下调，不往上加**
   （日常画面压低；但明确出现攻击/异象/真相的，**该多高给多高**）
3. **低分反例清单**
   （数数/吃饭/走路/日常对话/动物卖萌/摆拍表情 → 一律 ≤0.3）

### 回归测试（防下次再犯）

| **必须高** | 屠万鬼谷 / 老者惊恐 / 黑熊扑来 / 持刀对峙 / 握棍怒吼 / 异象发光 | L2-L3 0.70-0.90 ✓ |

### ★★ 关键工程教训（四条，都是实测踩出来的）

#### 1. 靠变速对齐时长是错的，必须从源头控制字数

TTS 实测语速 **3.22 字/秒**（Breeze TTS 2 / 纪录片音色），
短剧解说标准是 5.5-6.0 字/秒。

初版文案 221 字 / 37 秒 = 5.9 字/秒 → 每段都要加速 2x 才能对齐，
**超过 atempo 安全上限 1.6，人声会发飘**。

**正解**：`chars_for_duration()` —— 写稿前先算字数上限
```
字数 = 目标秒数 × 5.0
```
按此重写：221 字 → **140 字**（3.78 字/秒），全部段落在预算内。

> **变速只能微调（0.75-1.25），不能用来对齐。文案长度必须在写稿阶段就定死。**

#### 2. 片段时长按「实际配音时长」定，不是拍脑袋

初版所有片段统一 3.0s，结果配音长短不一，时间轴对不上。
正解：`片段时长 = 实测配音时长 + 0.25s（呼吸留白）`
→ 各段 2.8-5.8s 不等，总长 43.16s。

#### 3. Windows 中文路径：ffmpeg subtitles 滤镜会崩

```
Error applying option 'original_size' to filter 'subtitles': Invalid argument
```
原因：`D:/...` 的盘符冒号被当成滤镜参数分隔符。
正解：`path.replace(':', '\:')` 转义后传入。

#### 4. ffmpeg filter_complex 拼接要顺序 append，不要手工拼 labels


**它还有两条我完全没意识到的规则**：
1. 原声段前后 0.2s 内 BGM **提前抽空**（J-cut 思路：声音先变，画面后变）
2. 版权规避是**量化配额**：单段原声 ≤5s、总时长占比 ≤25%、连续原声 ≤8s

### 新增 `scripts/mix_v6.py`

按 13 号规范重写，实现真正的 duck：

```python
# 解说段 BGM → 0.20（垫底不抢）
# 原声段 BGM → 0.05（几乎抽空，让原声当主角）
# 段间空白 → 0.30
"volume=enable='between(t,6.06,10.56)':volume=0.05"
```

### ★ ffmpeg 实测坑（这次测出来的）

**① `volume` 多段规则不能用 `|` 串联**
```
volume=0.3|between(t,1,3):volume=0.05
→ No option name near '0.05'   （`|` 被当滤镜分隔符）
```

**正解**：用逗号串联 + `between()` 用**单引号包裹**
```
volume=enable='between(t,0,5)':volume=0.30,volume=enable='between(t,5,9)':volume=0.05
→ 实测 OK
```

**② Windows 中文路径烧字幕的正解**
`srt` 复制到纯 ASCII 临时路径（`%TEMP%/wb_sub.srt`），再调用：
```python
sp = str(tmp_srt).replace(':', chr(92) + ':')
vf = "subtitles=filename='" + sp + "':force_style='" + style + "'"
```
**转义盘符冒号 + 纯 ASCII 路径，两个条件缺一不可。**

## 十七、★★★ 配音问题：音色选错（2026-08-12 00:14）

### 用户反馈

> 「配音有问题」

### 量化诊断（实测四个音色的语速）

用同一句「注意看，这个小女孩叫小美」（12 字）实测：

| 音色 | 时长 | 语速 | 判断 |
|---|---|---|---|
| **谭湘文徐浩伦** | 2.00s | **6.00 字/秒** | ✅ **短剧解说标准** |
| 小棠 | 2.56s | 4.69 | 偏慢 |
| 子言 | 2.64s | 4.55 | 偏慢 |
| **纪录片（我一直在用）** | 3.20s | **3.75 字/秒** | ❌ **太慢** |

**短剧解说标准语速是 5.0-6.0 字/秒**，我用的「纪录片」只有 3.75。

### 根因：我没按技能推荐选音色

`本地配音工坊` §0.1 明确写着：
> **默认建议：不传 `--engine`（走 breeze）+ `--voice 谭湘文徐浩伦`**

我在 `series_tts.py` 里写死了 `voice='纪录片'`（因为「纪录片」听起来像解说用途）。
**音色用途标签 ≠ 语速适合。**

### ★★ 连带发现：段长被强行凑长

换音色后暴露出另一个问题：

| 段 | 实际配音 | 原段长 | 缺口 |
|---|---|---|---|
| 1 | 2.00s | 6.06s | **画面比配音长 3 倍** |
| 3 | 1.92s | 4.46s | 2.3 倍 |
| 6 | 3.60s | 6.06s | 1.7 倍 |

**我之前是按「固定段长」倒推配音源**，导致新版配音出现大片空白。

**正解（已改）**：
```python
s['duration'] = round(d + 0.5, 2)   # 实际配音 + 0.5s 呼吸
```
成片从 28.7s **收紧到 20.5s**，节奏立刻正常。

### 已固化的两条规则

**① `series_tts.py` 默认音色改为 `DEFAULT_VOICE = '谭湘文徐浩伦'`**
```python
DEFAULT_VOICE = '谭湘文徐浩伦'   # 技能推荐 + 实测 6.00 字/秒
# 对比：纪录片 3.75（太慢）/ 小棠 4.69 / 子言 4.55
```

**② 段长永远由实际配音决定，不由文案预算决定**
- 旧逻辑：`dur=预设 → 配音去凑`（错，会强行变速）
- 新逻辑：`配音 → 实测时长 → 段长 = 配音 + 0.5s`
