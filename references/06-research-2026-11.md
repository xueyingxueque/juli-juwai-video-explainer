## 1. 法规与合规（采纳）

| # | 可核验事实 | 来源 |
|---|---|---|
| 1.1 | 《人工智能生成合成内容标识办法》**2025-09-01 施行**；**第四条**：视频应在「**起始画面和视频播放周边的适当位置**」添加显式标识，末尾/中间为可选；音频在起始/末尾/中间；文本在起始/末尾/中间 | [1-1][1-2][1-6] |
| 1.2 | **第五条**（制作侧隐式要素）：生成合成内容属性信息、服务提供者名称或编码、内容编号；**第六条**（传播侧）：生成属性、传播平台名称或编码、内容编号；鼓励添加水印 | [1-1][1-3][1-5] |
| 1.3 | 强标实现范例（媒体转述）：显式文字**高度不低于画面最短边 5%**、**持续不少于 2 秒**；1080×1920 最短边 1080 → 约 **54px** | [1-6]（**存疑**，见 §8） |
| 1.4 | 字段名须含 AIGC 标识符号；元数据要素含哈希校验值等 | [1-3][1-5]（**存疑**，见 §8） |
| 1.5 | 《微短剧发展管理办法》（总局令第 16 号）**2026-09-01 施行**，第 34 条要求每集明显位置提示；广电总局 **2026-11-06** 新一轮「低俗化同质化」专项治理（11/1–12 月底）明确治理「改头换面、反复播出」「推荐同质化」 | [1-1][1-8] |
| 1.6 | 中央网信办规范短视频内容标注：**6 类必选标签**（含有虚构演绎内容 / 含有AI生成内容 / 含有营销信息 / 内容为转载 / 内容为个人观点 / 无需标注）；内容标注设为**发布必经环节** | [1-9] |
| 1.7 | 司法口径：解说二创若形成对原片的「**实质性替代**」，同义转换不构成合理使用 | [1-15] |

**落地**：
- `config/engine.json → compliance_policy.ai_label_positions` 由「片头前3秒 / 封面 / 简介」**更正**为法规原文「起始画面 / 播放周边」；新增 `publish_side_positions`（封面文案 / 发布简介 / 发布页必选标签）、`explicit_label_spec`、`implicit_metadata_spec`、`publish_labels`。
- `scripts/publish_kit.py` 产出可直接复制的三处文案 + 6 类标签推荐 + 显式标识实测核对；**不自动发布**（F7）。
- `scripts/compliance.py stamp` 的 `comment` 已含生成主体/版本/作品编号/AI 参与比例/生成时间，对应 1.2 的制作要素；**哈希校验值当前未写入**，如实列为已知缺口。

> **工程推断**：引擎自身不烧显式标识文字（会改动画面与冷开场），因此把落位做成物料清单交由发布环节执行，
> 并把「有没有真的写进成片」的**隐式标识**做成可实测项。这是把人工纪律变成可核对清单，不是替代人工审核。

## 2. 同质化与画面去重（采纳）

| # | 结论 | 性质 |
|---|---|---|
| 2.1 | 平台侧治理「改头换面、反复播出」「推荐同质化」，同质内容限流/下架有明确政策依据 | 事实 [1-8] |
| 2.2 | pHash 汉明距离经验：0–2 几乎相同 / 3–5 高相似 / 6–10 中等；去重建议 ≤5；双哈希策略 pHash≤10 且 dHash≤6 可减少误报 | 二手经验 [2-2][2-3]（**存疑**） |
| 2.3 | 平台查重信号含帧级指纹、语义相似、文案 n-gram；`anti_dup.py` 的色相/噪点变换只对弱指纹有效 | 事实 + 推断 [2-5] |

**落地**：新增 `scripts/visual_dedupe.py`（第六层实证）+ `config/engine.json → visual_dedupe_policy`。
纯 ffmpeg 抽帧 → 灰度 rawvideo 字节 → dHash（**不依赖 Pillow**）→ 跨集汉明距离比对。
`max_hamming_distance=6` 取自 2.2 的 dHash 经验值，但**只作报告阈值、不进硬门**，配置里明确标注为待自校准的经验值。

> **架构判断**：`episode_dedupe.py` 管「写稿时声明不重复」（spec 元数据硬闸），
> `visual_dedupe.py` 管「成片画面确实不重复」（出片后实证报告）。两者互补、不可互相替代 —
> 与「实切 X 与度量 X 必须同一真相源」同源：声明层有闸门、实证层没有，改一处必漏另一处。
>
> **反直觉结论**：`anti_dup.py` 不应定位为「规避平台查重手段」，而应定位为
> **变换鲁棒性自测**（验证自家去重判据在轻微色彩/噪点扰动下是否仍成立）。规避式几何变换
> 与 1.5 的治理方向相悖，本版**不扩展几何变换层**（§4.2 缺口 ⑥ 保持如实声明）。

## 3. 烧录硬字幕擦除（不采纳）

调研到的本地方案：OpenCV inpaint / ffmpeg `delogo` / ProPainter、STTN、E2FGVI、LAMA 等视频修复模型 [3-1][3-3]。

**决策：维持 P87 现状（ASS 底栏压盖 + 交付前抽帧），不改成默认真擦除。** 三条理由：
1. **合规风险**：原片烧录字幕可能承载片名/版权/标识信息，擦除在 1.1 的标识框架下有被认定为
   「篡改、隐匿标识」的风险 [1-1]（**工程推断**，非法律结论）。
2. **代价不可接受**：视频修复类模型对竖屏 5 分钟成片需几十分钟/条，且帧间易出现修补闪烁 [3-3]；
   与本引擎「批量出片」定位冲突。
3. **现状可用**：`delogo` 属模糊遮挡，视觉上仍是「压盖」的变体，不比现有 ASS 底栏更优 [3-2]。

> 这条是**明确的不采纳决策**，不是遗漏。写进本文是为了下次不再反复调研同一个问题。

## 4. 自动化媒体 QC（采纳）

| 检查 | ffmpeg 方案（本机已验证二进制存在） | 落地 |
|---|---|---|
| 黑帧 | `blackdetect=d=0.5:pix_th=0.10:pic_th=0.98` | `scripts/media_qc.py` |
| 冻结/卡帧 | `freezedetect=n=0.001:d=1.0`（n 为噪声阈值 ≈ -60dB） | 同上 |
| 超长静音 | `silencedetect=noise=-45dB:d=1.2` | 同上（记忆铁律：不用 `astats`） |
| 音画时长差 | `ffprobe -show_streams` 双流 duration | 同上 |
| 响度/真峰值 | `ebur128=peak=true` / `loudnorm print_format=json` | **已有**：`scripts/build.py` verify，不重复 |
| 混音均匀度 | 按 cue 分段 `volumedetect` | **已有**：`scripts/quality_gate.py` hard_mix_uniformity，不重复 |

**关键纪律**：ffmpeg 滤镜「无异常输出」≠ 完全正常；滤镜执行失败/输出不可解析一律记
`unknown` 并走保守路径（P84「读不到 ≠ 没有」）。`media_qc.py` 默认只报告不拦，
`--strict` 才把 fail/unknown 判失败 — 新判据不得否定历史成片。

> 本地全链审计确认：升级前 `scripts/` 下 **零 blackdetect / 零 freezedetect**，
> `build.verify()` 只管音频、`hard_technical()` 只管 ffprobe 元数据，纯视觉故障是最后一个客观盲区。

## 5. 内容结构与留存（存疑，不作阈值）

二手运营文给出「完播率提升 40% / 前 3 秒跳出 55% / 前 3 秒必给冲突」等数字与做法 [5-1][5-2][5-4]。
**这些数字无权威来源、口径不可核验，一律不写进 `config/engine.json`，不进任何质检硬门。**

可保留的、与本引擎已有方法论一致的方向性结论（仅作 `01-content-craft.md` 参考）：
信息密度、情绪曲线、冷开场倒叙、多集连载差异化选镜。本引擎的 `content_policy` 六段骨架
与 F8 镜头重排纪律已覆盖这些，无需引入新阈值。

| AIGC 判据收口 + stamp 幂等 + 接进 deliver | **采纳（治根）** | `compliance.py` / `produce.py` / `eval_skill.py` |

| 跨集人物归一 / S2 证据绑定 | 未采纳（需 NER/VLM，超出本次范围） | §4.2 缺口保持如实声明 |
