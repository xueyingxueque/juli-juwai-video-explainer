## 一、★★★ 根因：问题不在技术层，在内容层

前面几轮我一直在修**音轨**（混音、响度、amix 参数）——那些是技术问题。

**但用户说「解说乱、剪辑乱、画面乱」，这三样都是内容问题。**

### 我犯的根本错误

读完 70 集的分解数据后，我**凭关键词抓片段**：
- 抓到「一个人屠了整个万鬼谷」
- 抓到「他一铁锹碎了元婴期期的血魔」
- 抓到「金色光柱从天而降」

**然后把这些当成了剧情主线。**

### 真相（读完全剧字幕后）

那些台词的 speaker 全是**「画外音」**——**是别人在吹牛，不是她在做**。

真实主线是：

```
1-4集   农村生活：爹失踪、娘病、狗护她
5-10集  上山找爹，捡石头遇见修仙老头
14-19集 种出灵萝卜（比胳膊还粗）
22-27集 卖菜修仙，修士疯抢（一根萝卜换一件法器）
31-33集 娘的病治好了
52-54集 村长叔叔接她进城
62-70集 得罪权贵，被追杀
```

**一个三岁农村女孩，靠种菜修仙养活母亲。**
比我之前写的「屠万鬼谷」「碎血魔」动人得多，而且**画面全部自带证据**。

## 二、★ 第二个错误：时间点靠猜

我按「集号 + 估算时间」选画面，抽帧一看：

```
第14集 t=4.15s → 发芽的芽苗（我以为会是巨型萝卜）
```

### 正解：所有时间点必须来自 VLM 分析结果

`episodes/E*.json` 里每帧都有：
```json
{
  "t": 45.56,
  "desc": "一个小女孩蹲在田地里，惊讶地看着一个巨大的萝卜，旁边有一只戴护目镜的狗",
  "subtitle_text": "这萝卜咋比俺胳膊还粗"
}
```

**先搜数据 → 拿到 desc 和字幕核对 → 确定时间点。**
不能凭集号猜。

检索脚本：
```python
KEYS = ['萝卜']
for f in glob('episodes/E*.json'):
    d = json.load(open(f))
    for fr in d['frames']:
        if any(k in fr['desc'] for k in KEYS):
            print(d['ep'], fr['t'], fr['desc'], fr['subtitle_text'])
```

### ★★ 铁律：出片前必须抽帧验证

**每一段都要抽帧看，不看就出片 = 前几轮犯的错。**

v3 实测：
| 段 | 时间点 | 验证结果 |
|---|---|---|
| 5 巨型萝卜 | 第14集 45.56s | ✅ 比脑袋还大的萝卜 + 「比俺胳膊还粗」 |
| 6 卖菜 | 第23集 11.13s | ✅ 钞票撒满桌 + 「加一件法器 1万两」 |

## 三、v3 最终方案（真实剧情线）

| # | 集/时间 | 类型 | 口播 | 画面依据 |
|---|---|---|---|---|
| 1 | 1集 4.10s | 解说 | 这个叫菊儿的小丫头，今年三岁 | 田里拔胡萝卜，「剩下的留给娘」 |
| 2 | 1集 61.44s | 解说 | 爹失踪半年，娘病着，她只有两条狗 | 「大黄大白菊儿交给你们了」 |
| 3 | 2集 11.72s | **纯原声** | —— | 护狗反击，方言原声更有劲 |
| 4 | 10集 67.22s | 解说 | 上山那天，白发老头给了她一块发光的石头 | 修仙老头给她住处 |
| 5 | 14集 45.56s | 解说 | 她种的萝卜，比她胳膊还粗 | ★ 巨大萝卜+狗 |
| 6 | 23集 11.13s | 解说 | 修仙界抢着买，一根萝卜换一件法器 | ★ 钞票+萝卜 |
| 7 | 32集 8.46s | 解说 | 最后，娘的病，是卖萝卜治好的 | 情感闭环回到开头 |

### 三个设计要点

**1. 情感闭环**
开头「娘」，结尾「娘的病治好了」——首尾呼应，比「屠万鬼谷→碎血魔」有力。

**2. 原声只用 1 处**
原片是方言口音（俺/恁/啥），念出来比解说自然。
但**只有原声段不写口播**，避免同一句话说两遍。

**3. 每句口播都有画面证据**
不写「画面给不出」的东西（动机、关系、时间），
不吹「画面说不清」的战绩（屠谷、碎血魔）。

## 四、v3 成片验证

```
结构：7 段（解说 6 / 原声 1）
口播 91 字 / 23.52s（**历史样例，低于现行 60s 下限，不可直接复用**）

[6/6] 烧字幕 + 校验
    视频 23.6s / 音轨 23.52s
    响度 -14.4 LUFS / 峰值 -1.5 dBTP
    扫描 46 个窗口，最低 -39.2 dB
    ✓ 全部校验通过
```

抽帧验证（16.5s 处 = 第6段卖菜）：
**修仙者围着菜摊、钞票飞起、字幕「加一件法器 1万两」** —— 与口播完全对应。

## 五、★★ 三条从源头解决的规则

| # | 规则 | 防止什么 |
|---|---|---|
| 1 | **先读全剧字幕搞懂剧情，再写解说** | 拿吹牛台词当主线 |
| 2 | **所有时间点来自 VLM 数据，不按集号猜** | 抽到芽苗而不是巨型萝卜 |
| 3 | **出片前逐段抽帧验证** | 画面与口播对不上 |

> **技术层的问题（音轨/混音/参数）修再多遍，
> 也救不了内容层的错误（剧情/画面/顺序）。**
> 用户说「混乱」时，先怀疑内容，再怀疑技术。

---

## 六、判断顺序（以后遇到「乱」）

```
1. 剧情线对不对？    ← 先读全剧字幕，别凭关键词抓
2. 画面选对了吗？    ← 时间点必须来自 VLM 数据，抽帧验证
3. 解说和画面对得上吗？ ← 一句话不能被说两遍
4. 音频技术上没问题吧？ ← 最后才查音轨
```

**我前三轮都从第 4 步开始查，所以一直修不对。**
