## 一、先搞清楚走哪条路

日常生产只有一条路：**清单驱动，一条命令**。

```bash
python scripts/produce.py --pilot <episodes.json> --prefix <集前缀>
```

`episodes.json` 写清「哪部剧、要出哪几集、叫什么标题、用什么音色」，
`produce.py` 把十步串成一条命令：预检去重 → VLM 采证据 → 组装 → BGM →
二创图 → 精确锚点插入 → TTS 渲染 → 质检 → 封面 → 交付。
**中断后重跑同一条命令即续跑**，配音按签名复用、二创图不白重出。

旧的「手工八步」已经降级为**调试单步**（附录 A），批量生产不要再手串。

## 二、从零跑通一集

### 步 0：确认素材真下完了

```bash
python scripts/watch_downloads.py once
```

看板 7 条判据全绿才算 READY（临时文件清零、集数达标、采样稳定、
静默窗口、每个 mp4 可解析、还有事可做）。用它避开「下载批次空档」被误判完成。

### 步 1：建档 + 字幕入库

```bash
python scripts/new_task.py --name <任务名> --dataset <素材目录> --episodes <集数>
python _tools/ingest_all.py <任务目录> <素材目录> 1 10    # 钩子版够用；长集按需补
```

### 步 2：读剧情、写 spec（内容层，由 Agent 主导）

```bash
python _tools/dump_lines.py <任务目录> 1 2 3 4 5 6 7 8    # 导出逐字台词
python scripts/shot_rank.py <素材目录> --ep 1 --top 20      # 可选：召回候选镜头
```

写 `_plan/spec-<ep>.json`：30–45 镜、预估 90–250s（比硬门 60–300s 更保守的写稿预算，最终以实测为准）、首镜 `cold_open`、
镜头按剧本 block 曲线重排（**不按集数顺序**）、锚点逐字照抄 ASR 分段原文、
不写 `tier`、不写 cta 段、解说词不含「——」「…」、原声段 `text` 留空。

写完过内容闸门：

```bash
python scripts/content_brief.py <任务目录> <ep> --strict
```

它会给出节奏预算、情绪链条、Kill List、每段插片理由与内容质量清单。

### 步 3：备齐 gencfg 与音色

- `_gencfg/<前缀>.json`：2 条二创图 + 3 条表情包 + 封面字段；
  `cover_main` **≤16 个汉字**，所有 `anchor` 必须是 spec 解说词的精确开头。
- `_plan/voice_ref.wav`：`extract_voice_ref.py` 从原片主角台词切参考音
  （商用前确认声音授权；无授权改用题材预设音色）。

### 步 4：填清单

把这一集写进 `_tools/episodes.json`（字段见 SKILL.md §0.3）。
多集时**按源集号分段**分配镜头，从源头保证画面零重复。

### 步 5：三道预检（秒级，别跳过）

```bash
python scripts/spec_precheck.py <任务> <ep> <gencfg> --pilot <清单>
python scripts/compliance.py check <任务> <ep> <gencfg>
python scripts/contracts.py --audit
```

第一道查 TTS 敌对字符/锚点/CTA/时长/跨集去重；第二道查营销词、
AI 标识清单与授权提醒；第三道查配置与代码有没有漂移。

### 步 6：出片

```bash
python scripts/produce.py --pilot <清单> --prefix <前缀>        # 真跑
python scripts/produce.py --pilot <清单> --prefix <前缀> --dry-run  # 先看会跑什么
```

成功判据是 `★ 全流程完成，成品齐全 ✓`。想重做封面：加 `--force cover`；
只想从某步开始：加 `--from build`。

### 步 7：验收

```bash
python scripts/deliver_check.py <任务> <ep> <前缀> <成片名> --title <标题> --series <剧名>
python scripts/compliance.py provenance <任务> <ep>          # 生成链路留痕
```

再**抽帧肉眼确认**画面（校验只管音频），特别是原片烧录字幕与解说字幕是否双层并存（P87）。

## 三、出片之后

- 交付文件在 `<素材目录>/解说成品/<前缀>-<标题>.mp4`。
- AI 隐式标识已由 `produce.py` 的 deliver 步**自动补标**（幂等 + 写后复核），无需手动执行；
  仅给历史成片补标时才单独跑 `compliance.py stamp <视频> --task … --ep … --apply`
  （`-c copy` 无损、留 `.pre-aigc` 备份；**改动交付物前先确认**）。
- 每轮收尾跑 `eval_skill.py` + `learn_from_runs.py`，
  复核 `learning_report.json` 的坑典候选，有新坑就同步 `evals.json` / `CHECKS` / 坑典索引。

## 附录 A：调试单步（仅排障用）

需要单独复现某一步时才用，完整列表见 SKILL.md §2.6：
`shot_evidence.py` → `assemble_plan.py` → `bgm_select.py` →
`gen_images.py` → `make_plan_v37.py` → `build.py` →
`quality_gate.py` → `make_cover.py` → `deliver.sh`。

⚠️ `deliver.sh` 第 3 参是 **out 目录下的集目录名**（通常是 prefix），
不是集号；传集号会找不到成片。

## 附录 B：常见失败

| 现象 | 先看哪里 |
|---|---|
| 改了 spec 但 build 还是老文案 | ev 没同步 → `delta_evidence.py`（produce.py 指纹级联会自动做） |
| 第 2 集和上一集画面重复 | `episode_dedupe.py` 零重叠硬闸会拦，按提示换源集/时段 |
| 成片没声音 / 后半段静音 | 坑典 P01（`amix duration=first`）/ P77（混音链） |
| 跑了很久没产出也没报错 | SKILL.md §4.1 → P83/P86，用 `auto_pilot.py` 推进 |
| 封面主标被裁 | 超过 16 字，压缩后 `--force cover` |
| 配置改了不生效 | `contracts.py --audit` 找硬编码副本 |
